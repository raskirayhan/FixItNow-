================================================================================
                         PROJECT SUMMARY - FixItNow
================================================================================

PROJECT NAME
    FixItNow

DESCRIPTION
    FixItNow is a full-stack home services marketplace platform that connects
    customers needing home services (plumbing, electrical, cleaning, painting)
    with verified technicians. The platform supports service browsing, booking
    management, secure Stripe payments, and a review system.

PROJECT PURPOSE
    To provide a seamless marketplace experience where customers can discover
    local technicians, book services, make secure payments, and leave reviews.
    Technicians can manage their profiles, accept or decline booking requests,
    and track their earnings. Administrators can monitor platform activity,
    manage users, and view analytics.

================================================================================
                      BACKEND OVERVIEW
================================================================================

    Architecture:
        - Express.js v5 with TypeScript
        - Modular structure: controllers, routes, middlewares, schemas
        - Prisma ORM for database access
        - JWT-based authentication with role-based access control

    Middleware:
        authenticateToken     Validates JWT and attaches user to request
        requireRole(roles[])  Restricts access to specified user roles
        validate(schema)      Zod schema validation for request bodies
        errorHandler          Global error handling with structured responses

    Controllers:
        authController        Registration, login, profile retrieval
        serviceController     Service CRUD, search with filters
        bookingController     Booking creation, status management
        paymentController     Stripe PaymentIntent creation, webhook handling
        reviewController      Review creation for completed bookings
        adminController       User management, stats, categories

================================================================================
                      AUTHENTICATION
================================================================================

    Mechanism: JWT (JSON Web Tokens)

    Flow:
        1. User registers or logs in via /api/auth/register or /api/auth/login
        2. Server validates credentials, generates JWT (7-day expiry)
        3. Token returned to client and stored in localStorage
        4. Client attaches token as Bearer header on all authenticated requests
        5. Server middleware validates token and attaches user info to request
        6. Role-based middleware restricts access to specific endpoints

    Password Security:
        - bcryptjs with 12 salt rounds
        - Passwords never returned in API responses

    Frontend Integration:
        - AuthContext manages global auth state
        - Auto-restores session from stored token on page load via /api/auth/me
        - ProtectedRoute component guards routes by auth status and role

================================================================================
                       API ENDPOINTS
================================================================================

    Health Check:
        GET /api/health                          (Public)

    Authentication:
        POST   /api/auth/register                (Public)
        POST   /api/auth/login                   (Public)
        GET    /api/auth/me                      (Authenticated)

    Services:
        GET    /api/services                     (Public - search, filter by category/rating)
        GET    /api/services/categories          (Public)
        GET    /api/services/:id                 (Public - service detail with reviews)
        GET    /api/services/technician/:id      (Public - technician's services)
        POST   /api/services                     (Technician only - create service)

    Bookings:
        POST   /api/bookings                     (Customer only - create booking)
        PATCH  /api/bookings/:id/status          (Customer/Technician - update status)
        GET    /api/bookings/customer            (Customer only - list bookings)
        GET    /api/bookings/technician          (Technician only - list bookings)

    Payments:
        POST   /api/payments/create              (Customer only - create Stripe PaymentIntent)
        POST   /api/payments/webhook             (Public - Stripe webhook callback)

    Reviews:
        POST   /api/reviews                      (Customer only - create review)

    Admin:
        GET    /api/admin/users                  (Admin only)
        PATCH  /api/admin/users/:id/ban          (Admin only - ban/unban user)
        GET    /api/admin/bookings               (Admin only)
        GET    /api/admin/stats                  (Admin only - dashboard stats)
        GET    /api/admin/categories             (Admin only)

================================================================================
                     INSTALLATION GUIDE
================================================================================

    Prerequisites:
        - Node.js v18+
        - PostgreSQL database
        - Stripe account (for payment features)

    Steps:
        1. Clone the repository
        2. Install frontend dependencies:
             cd frontend && npm install
        3. Install backend dependencies:
             cd backend && npm install
        4. Configure environment variables (see Environment Variables section)
        5. Set up the database:
             cd backend && npx prisma db push
        6. Seed the database:
             cd backend && npm run db:seed

================================================================================
                     RUNNING FRONTEND
================================================================================

    Development:
        From root:     npm run dev:frontend
        From frontend: cd frontend && npm run dev

    The frontend runs on http://localhost:5173 by default.
    API requests are proxied to http://localhost:5000 via Vite config.

================================================================================
                     RUNNING BACKEND
================================================================================

    Development:
        From root:     npm run dev:backend
        From backend:  cd backend && npm run dev

    Production:
        Build:         cd backend && npm run build
        Start:         cd backend && npm run start

    The backend runs on http://localhost:5000 by default.

================================================================================
                         DATA FLOW
================================================================================

    1. BROWSE SERVICES:
       Home page -> GET /api/services -> Display service cards with ratings

    2. BOOK SERVICE:
       Customer clicks "Book" -> POST /api/bookings -> Status: REQUESTED
       -> Technician sees request in dashboard

    3. ACCEPT/DECLINE:
       Technician accepts -> PATCH /api/bookings/:id/status -> Status: ACCEPTED
       -> Customer sees accepted booking

    4. PAYMENT:
       Customer goes to checkout -> POST /api/payments/create
       -> Stripe PaymentElement renders -> Payment confirmed
       -> Webhook: Status -> PAID

    5. SERVICE DELIVERY:
       Technician marks in-progress -> Status: IN_PROGRESS
       Technician completes -> Status: COMPLETED

    6. REVIEW:
       Customer leaves review -> POST /api/reviews -> Rating + comment
       -> Displayed on service detail page
